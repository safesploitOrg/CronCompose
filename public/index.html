Good to know

User vs system crontab

User crontabs edited with crontab -e do not include a username. System files such as /etc/crontab and /etc/cron.d/* require one. An administrator can edit another user’s crontab using crontab -u username -e.

Day-of-month and weekday

Under Cronie, if both day fields are restricted (not wildcard-led), either day field can trigger the job. The weekday selector previews that field only, not all possible execution dates.

Extended scheduling

The daemon triggers on the selected weekdays or each day for month end; the generated shell condition limits actual command execution. Requires GNU date in the trusted PATH and /bin/sh. Ensure the schedule and date command use the same timezone. Percent signs inside extended commands are not supported; place such commands in a separate script.

Timezone & DST

Check the cron host’s timezone, daemon implementation and daylight saving behaviour. This tool does not calculate forthcoming execution times.

Command environment

Use absolute command paths. Check permissions, PATH, environment variables and cron’s percent-sign processing. Review the generated entry before installing it. A syntactically valid entry does not guarantee the command will work.
